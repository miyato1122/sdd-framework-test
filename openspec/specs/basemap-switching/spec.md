# basemap-switching Specification

## Purpose

地図の背景タイルを複数の候補（OSM／国土地理院 標準地図／国土地理院 シームレス写真／国土地理院 白地図）に加え、ユーザーが独自に追加した任意個（0 以上）のカスタム背景地図からユーザーが排他選択できる機能と、その UI コントロールの配置・初期状態・出典表示の整合性、ならびにカスタム背景地図の追加・編集・削除・永続化を定義するケイパビリティ。

## Requirements

### Requirement: 背景地図を 4 種類からラジオで排他選択できる

システムは、地図の背景タイルとして、以下の 4 種類のプリセットと、ユーザーが独自に追加した任意個（0 以上）のカスタム背景地図をラジオで排他選択できるようにしなければならない（SHALL）。同時に複数の背景地図が可視であってはならない（MUST NOT）。

プリセット 4 種類は固定であり、本変更により削除・改名されない:

| 表示ラベル | タイル提供元 / 種類 |
| --- | --- |
| OSM | OpenStreetMap 標準タイル |
| 地理院地図 | 国土地理院 標準地図（`std`） |
| 航空写真 | 国土地理院 シームレス写真（`seamlessphoto`） |
| 白地図 | 国土地理院 白地図（`blank`） |

ユーザー追加分のラベル・タイル URL・出典・zoom 範囲は登録時のフォーム入力に従う。排他切替は、プリセット・ユーザー追加分のいずれであっても、選択された 1 件のみを `visibility: 'visible'`、他のすべての背景レイヤーを `visibility: 'none'` に設定することで実現する。

#### Scenario: 初回アクセス時の初期表示は OSM である

- **WHEN** 当該オリジンに対する IndexedDB に永続化値が無い状態でページを新規に読み込み地図が描画される
- **THEN** 背景地図として OSM が表示されており、ラジオ一覧の `OSM` が選択状態（checked）になっている

#### Scenario: 背景地図を地理院地図に切り替えられる

- **WHEN** ユーザーが切替コントロールで「地理院地図」のラジオを選択する
- **THEN** 背景タイルが国土地理院 標準地図（`std`）に切り替わり、OSM・航空写真・白地図および全ユーザー追加背景地図のレイヤーは非表示になっている

#### Scenario: 背景地図を航空写真に切り替えられる

- **WHEN** ユーザーが切替コントロールで「航空写真」のラジオを選択する
- **THEN** 背景タイルが国土地理院 シームレス写真（`seamlessphoto`）に切り替わり、他のすべての背景レイヤー（プリセット・ユーザー追加分）は非表示になっている

#### Scenario: 背景地図を白地図に切り替えられる

- **WHEN** ユーザーが切替コントロールで「白地図」のラジオを選択する
- **THEN** 背景タイルが国土地理院 白地図（`blank`）に切り替わり、他のすべての背景レイヤー（プリセット・ユーザー追加分）は非表示になっている

#### Scenario: 切替後に OSM へ戻せる

- **WHEN** OSM 以外を選択中の状態で、ユーザーが「OSM」のラジオを再選択する
- **THEN** 背景タイルが OSM に戻り、他のすべての背景レイヤー(プリセット・ユーザー追加分)は非表示になっている

#### Scenario: 背景地図をユーザー追加分に切り替えられる

- **WHEN** カスタム背景地図が 1 件以上一覧に存在する状態で、ユーザーがそのうちのいずれかのラジオを選択する
- **THEN** 選択されたカスタム背景地図のタイルが表示され、プリセット 4 つおよび他のユーザー追加分のレイヤーは非表示になっている

#### Scenario: ユーザー追加分からプリセットへ戻せる

- **WHEN** ユーザー追加のカスタム背景地図を選択中の状態で、ユーザーが任意のプリセット（OSM など）のラジオを再選択する
- **THEN** 背景タイルが選択されたプリセットに切り替わり、ユーザー追加分のレイヤーは非表示になっている

### Requirement: 背景地図切替コントロールは地図の左下に表示する

システムは、背景地図を切り替える UI コントロールを地図の左下（MapLibre の `bottom-left` 位置）に配置しなければならない（SHALL）。コントロールは MapLibre 標準の他コントロール（左上・右上・右下）と視覚的に競合してはならない（MUST NOT）。

#### Scenario: コントロールが左下に配置される

- **WHEN** 地図が描画完了している
- **THEN** 背景地図切替コントロールが地図ビューの左下に表示されており、左上の OpacityControl（ハザード）、右上の OpacityControl（指定緊急避難場所）、右下の GeolocateControl / TerrainControl と重なっていない

#### Scenario: コントロールが MapLibre 標準のコントロール外観に揃う

- **WHEN** コントロールが描画されている
- **THEN** コンテナ要素は MapLibre 標準のコントロールクラス（`maplibregl-ctrl maplibregl-ctrl-group`）を持ち、白い角丸カードに沿った外観で表示される

### Requirement: 出典表示は表示中の背景地図に追従して切り替わる

システムは、地図右下の出典（attribution）表示を、現在可視である背景地図ソースに応じた文字列に自動で切り替えなければならない（SHALL）。可視でない背景地図ソースの出典が表示されてはならない（MUST NOT）。

プリセット 4 種類の出典文字列は以下とする:

| 背景地図 | 出典文字列に含まれるリンク／文言 |
| --- | --- |
| OSM | `OpenStreetMap`（リンク先 `http://www.openstreetmap.org/copyright`） |
| 地理院地図 | `地理院タイル`（リンク先 `https://maps.gsi.go.jp/development/ichiran.html`） |
| 航空写真 | `地理院タイル`（リンク先 `https://maps.gsi.go.jp/development/ichiran.html`） |
| 白地図 | `地理院タイル`（リンク先 `https://maps.gsi.go.jp/development/ichiran.html`） |

ユーザー追加のカスタム背景地図の出典は、登録時に入力された「出典テキスト」と「出典リンク URL」から、別 Requirement で規定する組み立てルールに従って生成された文字列とする。テキスト・リンク URL のいずれも未指定の場合は、当該カスタム背景地図由来の出典文字列は出力しない。

#### Scenario: OSM 表示中は OSM の出典が表示される

- **WHEN** 背景地図として OSM が選択されており、ハザード・指定緊急避難場所など他レイヤーが非表示である
- **THEN** 地図右下の出典に `OpenStreetMap` のリンクが含まれ、`地理院タイル` のリンクおよびユーザー追加分の出典は含まれない

#### Scenario: 地理院地図／航空写真／白地図 表示中は地理院タイルの出典が表示される

- **WHEN** 背景地図として地理院地図・航空写真・白地図のいずれかが選択されており、ハザード・指定緊急避難場所など他レイヤーが非表示である
- **THEN** 地図右下の出典に `地理院タイル` のリンクが含まれ、`OpenStreetMap` のリンクおよびユーザー追加分の出典は含まれない

#### Scenario: ハザードや指定緊急避難場所と背景の出典が併記される

- **WHEN** 任意の背景地図（プリセット／ユーザー追加問わず）に加え、ハザードマップまたは指定緊急避難場所のレイヤーが可視である
- **THEN** 背景地図に対応する出典に加え、可視であるハザードマップポータルサイトおよび／または国土地理院:指定緊急避難場所データの出典が同時に表示される

#### Scenario: ユーザー追加の背景地図選択時はその出典が表示される

- **WHEN** ユーザーがカスタム背景地図（出典テキスト／リンク URL のいずれか以上を登録済み）を選択する
- **THEN** 地図右下の出典に、当該カスタム背景地図の登録時入力から組み立てられた出典文字列が含まれ、プリセット由来の出典（`OpenStreetMap`・`地理院タイル`）は含まれない

### Requirement: 背景地図切替後も既存機能が回帰なく動作する

システムは、背景地図のいずれを選択中であっても、以下の既存機能を従来どおり動作させなければならない（SHALL）。背景地図の切替が既存機能を破壊してはならない（MUST NOT）。

- 左上 `OpacityControl` によるハザードマップ（洪水・高潮・津波・土石流・急傾斜・地滑り）の表示切替
- 右上 `OpacityControl` による指定緊急避難場所（`skhb-1-layer` 〜 `skhb-8-layer`）の表示切替
- `GeolocateControl` による現在地取得と、ズーム 7 以上での「現在地 → 最寄り避難場所」ライン描画
- `TerrainControl` による 3D 地形のトグル、および `hillshade` レイヤーの描画
- 指定緊急避難場所地物に対するクリック時ポップアップ表示、ホバー時のカーソル変更

#### Scenario: 背景切替後もハザード重ね合わせが動作する

- **WHEN** 任意の背景地図を選択した状態で、左上 `OpacityControl` から任意のハザードマップを ON にする
- **THEN** 対応するハザードレイヤーが背景地図の上に半透明で表示され、再度 OFF にすると非表示に戻る

#### Scenario: 背景切替後も指定緊急避難場所の切替が動作する

- **WHEN** 任意の背景地図を選択した状態で、右上 `OpacityControl` から任意の指定緊急避難場所カテゴリを選択する
- **THEN** 対応する `skhb-*-layer` が背景地図の上に表示される

#### Scenario: 背景切替後も現在地ラインが描画される

- **WHEN** 任意の背景地図を選択した状態で、ブラウザの位置情報を許可しズームを 7 以上に拡大する
- **THEN** 現在地と、有効化中の `skhb-*-layer` 内で最も近い地物との間に青いライン（`route-layer`）が背景地図の上に描画される

#### Scenario: 背景切替後も 3D 地形が動作する

- **WHEN** 任意の背景地図を選択した状態で、右下に追加された `TerrainControl` を有効化する
- **THEN** 地理院標高タイルを用いた陰影（`hillshade`）と 3D 地形表示が反映され、背景タイルの上に陰影が乗る

### Requirement: 各背景タイルソースを規定の URL と zoom 範囲で定義する

システムは、背景地図用の各 raster source を以下の URL テンプレートと zoom 範囲で定義しなければならない（SHALL）。

| source id | URL テンプレート | minzoom | maxzoom |
| --- | --- | --- | --- |
| `osm` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | （既定） | `19` |
| `gsi_std` | `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png` | （既定） | `18` |
| `gsi_photo` | `https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg` | `2` | `18` |
| `gsi_blank` | `https://cyberjapandata.gsi.go.jp/xyz/blank/{z}/{x}/{y}.png` | `5` | `14` |

白地図 source の `maxzoom` を超えるズームレベルでは、MapLibre 既定のオーバーズーム描画（低ズームタイルの引き伸ばし）を許容する。`gsi_blank` の `maxzoom` を 14 より高い値にしてはならない（MUST NOT）。

#### Scenario: 白地図は z14 を超えてもオーバーズームで表示される

- **WHEN** 背景に白地図を選択した状態で、地図のズームレベルを 15 以上に拡大する
- **THEN** ブラウザのネットワークログに `gsi_blank` の z15 以降のタイルリクエストが発生せず、画面には z14 までのタイルが引き伸ばされて表示される

#### Scenario: 各 source の URL が規定どおりである

- **WHEN** `main.js` の `style.sources` 定義を確認する
- **THEN** `osm` / `gsi_std` / `gsi_photo` / `gsi_blank` の各 source の `tiles` 配列に上表の URL テンプレートが、`maxzoom` / `minzoom` に上表の値が、それぞれ設定されている

### Requirement: ユーザーが独自の背景地図を追加・編集するためのフォームを提供する

システムは、背景地図切替コントロール（左下）のラジオ一覧末尾に「背景地図を追加」ボタンを表示し、押下によりカスタム背景地図の入力フォーム（モーダルダイアログ）を **追加モード** で表示しなければならない（SHALL）。また、カスタム背景地図各行の操作メニュー（`⋮`）から「編集」が選択された場合、同じフォームを **編集モード** で表示しなければならない（SHALL）。

両モードで共通の入力欄:

- **名称**（必須）
- **タイル URL**（必須・`{z}`/`{x}`/`{y}` を含む XYZ テンプレート）
- **出典テキスト**（任意）
- **出典リンク URL**（任意）
- **詳細設定**（折りたたみ・任意）: `minzoom` および `maxzoom`

モード差分:

| 要素 | 追加モード | 編集モード |
| --- | --- | --- |
| ダイアログタイトル | `背景地図を追加` | `背景地図を編集` |
| 各入力欄 | 空 | 対象レコードの既存値を prefill |
| タイル URL 入力 | 編集可 | **`readonly` 属性を付与し変更不可** |
| 送信ボタン文言 | `追加` | `保存` |

送信成功時の挙動:

- **追加モード**: 新規 `id`（`crypto.randomUUID()`）でレコードを生成し、ラジオ一覧の末尾（追加ボタンの直前）に追加し、その背景地図を選択状態（checked）にする。
- **編集モード**: 既存 `id` を保持したままレコードを上書きする。一覧上の表示順は維持する。編集対象が編集時点で選択中であった場合、編集後も選択中の状態を維持する。

フォームのキャンセル時にはいかなる変更も加えてはならない（MUST NOT）。

#### Scenario: 追加ボタンが一覧末尾に表示される

- **WHEN** 地図の描画が完了している
- **THEN** 背景地図切替コントロール内のラジオ一覧の末尾に「背景地図を追加」ボタンが表示されている

#### Scenario: 追加ボタン押下で追加モードのフォームが表示される

- **WHEN** ユーザーが「背景地図を追加」ボタンを押下する
- **THEN** モーダルダイアログとしてフォームが表示され、タイトルが `背景地図を追加`、すべての入力欄が空、タイル URL 欄が編集可能、送信ボタン文言が `追加` である

#### Scenario: フォーム送信で新しい背景地図が一覧に追加され選択される

- **WHEN** 追加モードのフォームに有効な値（名称・有効な HTTPS タイル URL を含む）を入力し送信する
- **THEN** ダイアログが閉じ、ラジオ一覧の末尾（追加ボタンの直前）に当該背景地図の項目が追加され、その項目がラジオ選択状態（checked）となり、地図の背景タイルがその地図に切り替わる

#### Scenario: 操作メニューから編集を選ぶと編集モードのフォームが表示される

- **WHEN** カスタム背景地図行の操作メニュー（`⋮`）を開き「編集」を選択する
- **THEN** モーダルダイアログとしてフォームが表示され、タイトルが `背景地図を編集`、各入力欄に当該背景地図の現在値が prefill されており、タイル URL 欄は `readonly` で編集不可、送信ボタン文言が `保存` である

#### Scenario: 編集モードで保存すると同一 ID で内容が上書きされる

- **WHEN** 編集モードのフォームで名称・出典テキスト・出典リンク URL・minzoom／maxzoom のいずれかを変更し送信する
- **THEN** ダイアログが閉じ、ラジオ一覧の当該行のラベル（変更があれば）が更新され、地図上の当該背景地図の出典・zoom 範囲（変更があれば）が更新される。一覧上の表示順は変わらず、ID も変わらない

#### Scenario: 選択中の背景地図を編集しても選択状態が維持される

- **WHEN** カスタム背景地図が選択中の状態で、その地図を編集モードで保存する
- **THEN** 編集後もそのカスタム背景地図がラジオ選択状態（checked）であり、地図上にも当該背景地図が表示され続けている

#### Scenario: フォームのキャンセルで状態が変化しない

- **WHEN** フォーム表示中（追加／編集どちらのモードでも）にユーザーがキャンセル操作（キャンセルボタンまたは Esc キー）を行う
- **THEN** ダイアログが閉じ、ラジオ一覧・地図表示・IndexedDB の永続化内容はいずれも変化しない

### Requirement: カスタム背景地図のフォーム入力は規定ルールで検証される

システムは、カスタム背景地図フォームの送信時に以下のルールで入力を検証しなければならない（SHALL）。本検証ルールは追加モードと編集モードの両方に等しく適用される。検証に失敗した場合、保存処理（追加・編集）を実行してはならず（MUST NOT）、当該フィールドの近傍にエラーメッセージを表示しなければならない（SHALL）。

- **名称**: 両端トリム後 1 文字以上 40 文字以下であること。
- **タイル URL**: `new URL(value)` でパース可能であり、`protocol` が `https:` であり、文字列に `{z}`・`{x}`・`{y}` のすべてが含まれること。
- **出典リンク URL**: 空文字、または `http:` もしくは `https:` で始まる有効な URL であること。それ以外のスキーム（例: `javascript:`、`data:`）は拒否しなければならない（MUST NOT 受け入れる）。
- **minzoom／maxzoom**: 空文字、または `0` 以上 `24` 以下の整数であること。両方指定された場合は `minzoom ≤ maxzoom` でなければならない。

#### Scenario: 名称が空のときは追加できない

- **WHEN** ユーザーが名称欄を空のままフォーム送信する
- **THEN** ダイアログは閉じず、名称欄の近傍に必須入力である旨のエラーメッセージが表示され、IndexedDB と一覧は変化しない

#### Scenario: タイル URL が HTTPS でないとき拒否する

- **WHEN** ユーザーがタイル URL に `http://example.com/{z}/{x}/{y}.png` を入力して送信する
- **THEN** ダイアログは閉じず、タイル URL 欄の近傍に HTTPS が必要である旨のエラーメッセージが表示され、IndexedDB と一覧は変化しない

#### Scenario: タイル URL に z/x/y プレースホルダが不足しているとき拒否する

- **WHEN** ユーザーがタイル URL に `https://example.com/{z}/{x}.png`（`{y}` 欠落）を入力して送信する
- **THEN** ダイアログは閉じず、タイル URL 欄の近傍にプレースホルダ不足のエラーメッセージが表示され、追加処理は実行されない

#### Scenario: 出典リンク URL が javascript スキームのとき拒否する

- **WHEN** ユーザーが出典リンク URL に `javascript:alert(1)` を入力して送信する
- **THEN** ダイアログは閉じず、出典リンク URL 欄の近傍に許可スキーム外である旨のエラーメッセージが表示され、追加処理は実行されない

#### Scenario: minzoom が maxzoom より大きいとき拒否する

- **WHEN** ユーザーが minzoom に `10`、maxzoom に `5` を入力して送信する
- **THEN** ダイアログは閉じず、zoom 範囲の不整合エラーメッセージが表示され、追加処理は実行されない

#### Scenario: 編集モードでも同じ検証ルールが適用される

- **WHEN** ユーザーが編集モードで名称欄を空に書き換えて送信する、または出典リンク URL を `javascript:alert(1)` に書き換えて送信する
- **THEN** ダイアログは閉じず、該当フィールドの近傍にエラーメッセージが表示され、IndexedDB と一覧と地図表示は変化しない

### Requirement: カスタム背景地図の出典はテキストとリンク URL から構造化して描画する

システムは、カスタム背景地図の出典文字列を生成する際、ユーザー入力 HTML を直接そのまま挿入してはならない（MUST NOT）。出典は、入力された **出典テキスト** と **出典リンク URL** からアプリ側で構造化して組み立て、テキストは HTML エスケープ、リンク URL は属性用エスケープを施した上で `<a href="...">テキスト</a>` 形式で出力しなければならない（SHALL）。

組み立てルールは以下とする:

| 出典テキスト | 出典リンク URL | 出力 |
| --- | --- | --- |
| あり | あり | `<a href="{escAttr(url)}" target="_blank" rel="noopener noreferrer">{escHtml(text)}</a>` |
| あり | なし | `{escHtml(text)}` |
| なし | あり | `<a href="{escAttr(url)}" target="_blank" rel="noopener noreferrer">{escHtml(url)}</a>` |
| なし | なし | 空文字（attribution 出力なし） |

#### Scenario: テキストとリンクの両方が指定されたときリンク付きで描画される

- **WHEN** カスタム背景地図を出典テキスト `自社地図` と出典リンク URL `https://example.com/copyright` で登録し、地図上でその背景を選択する
- **THEN** 地図右下の出典に `<a href="https://example.com/copyright" target="_blank" rel="noopener noreferrer">自社地図</a>` が含まれる

#### Scenario: テキストに HTML 特殊文字が含まれてもエスケープされる

- **WHEN** カスタム背景地図を出典テキスト `<script>alert(1)</script>` で登録し、地図上でその背景を選択する
- **THEN** 地図右下の出典には `<script>` タグが DOM 上のスクリプト要素としては存在せず、エスケープされた文字列として表示される

#### Scenario: テキスト・リンクともに未指定なら出典は追加されない

- **WHEN** カスタム背景地図を出典テキスト・出典リンク URL ともに空で登録し、地図上でその背景を選択する
- **THEN** 地図右下の attribution コントロールに当該カスタム背景地図由来の文字列・要素は追加されない

### Requirement: カスタム背景地図の各行には編集・削除の操作メニューを提供する

システムは、ユーザー追加の各背景地図行に操作メニューボタン（`⋮`）を表示し、クリックで「編集」「削除」の 2 項目を含むドロップダウンメニューを開かなければならない（SHALL）。プリセット 4 種類の行に操作メニューボタンを表示してはならない（MUST NOT）。

#### Scenario: カスタム背景地図行に操作メニューボタンが表示される

- **WHEN** ユーザーがフォームから少なくとも 1 件のカスタム背景地図を追加した状態でラジオ一覧を見る
- **THEN** 追加されたカスタム背景地図行の右端に操作メニューボタン（`⋮`）が表示されており、プリセット 4 行（OSM／地理院地図／航空写真／白地図）には操作メニューボタンが表示されていない

#### Scenario: 操作メニューを開くと編集・削除の項目が見える

- **WHEN** ユーザーがカスタム背景地図行の操作メニューボタン（`⋮`）を押下する
- **THEN** ドロップダウンメニューが開き、「編集」と「削除」の 2 項目が表示されている

### Requirement: カスタム背景地図は操作メニューから削除できる

システムは、カスタム背景地図行の操作メニューから「削除」が選択された際、まずユーザーに対し削除対象の名称を含む独自モーダル確認ダイアログ（追加・編集フォームと同じく `<dialog>.showModal()` で画面中央に表示するモーダル）を表示し、ユーザーが「削除」を確定した場合に限り、当該背景地図を排他切替の対象から外し、Source／Layer を地図から取り除き、IndexedDB 上の定義からも除去しなければならない（SHALL）。確認ダイアログでキャンセル／Esc 等により閉じられた場合、システムはラジオ一覧・地図表示・IndexedDB のいずれも変更してはならない（MUST NOT）。

確認ダイアログは破壊的操作であることを視覚的に伝えるため、確認（削除）ボタンを赤系の背景色で表示しなければならない（SHALL）。

削除対象が削除時点で選択中であった場合、システムは選択を `osm-layer` にフォールバックさせ、選択中 ID の永続化値も `osm-layer` に更新しなければならない（SHALL）。

UI 表現として、操作メニュー内の「削除」項目は破壊的操作であることが視覚的に判別できるよう赤系統の文字色で表示しなければならない（SHALL）。一方「編集」項目は破壊的でない通常操作であることを示す青系統の文字色で表示しなければならない（SHALL）。

#### Scenario: 削除選択で確認モーダルが画面中央に表示される

- **WHEN** ユーザーがカスタム背景地図行の操作メニューから「削除」を選択する
- **THEN** 独自モーダル（追加・編集フォームと同様の `<dialog>` ベースで画面中央に表示され、背景はバックドロップで暗転する）が開き、対象背景地図の名称を含むメッセージと、キャンセル／削除（赤系）の 2 ボタンが表示される

#### Scenario: 削除確認で「削除」を押したとき一覧と地図から除去される

- **WHEN** ユーザーが削除確認モーダルで「削除」ボタンを押下する
- **THEN** モーダルが閉じ、その行がラジオ一覧から消え、当該レイヤー／ソースが `map.getStyle().layers`／`map.getStyle().sources` からも消え、再アクセス時に該当の背景地図は復元されない

#### Scenario: 削除確認でキャンセルしたとき状態が変化しない

- **WHEN** ユーザーが削除確認モーダルで「キャンセル」を押下する、または Esc キーで閉じる
- **THEN** モーダルが閉じ、ラジオ一覧・地図表示・IndexedDB のいずれも変化しない

#### Scenario: 選択中のカスタム背景地図を削除すると OSM にフォールバックする

- **WHEN** カスタム背景地図を選択中の状態で、その行の操作メニューから「削除」を選択し、確認モーダルで「削除」を確定する
- **THEN** 削除が反映されたうえで、ラジオの選択状態が `OSM` に移り、地図の背景が OSM に切り替わる。リロードしても OSM が選択された状態で表示される

#### Scenario: 編集項目は青系、削除項目は赤系の文字色で表示される

- **WHEN** ユーザーがカスタム背景地図行の操作メニュー（`⋮`）を開く
- **THEN** ドロップダウン内の「編集」が青系の文字色で、「削除」が赤系の文字色で表示されている

### Requirement: カスタム背景地図は操作メニューから編集できる

システムは、カスタム背景地図行の操作メニューから「編集」が選択された際、対象レコードの現在値を prefill した編集モードのフォームを表示し、ユーザーが名称・出典テキスト・出典リンク URL・minzoom・maxzoom を変更して保存できるようにしなければならない（SHALL）。タイル URL は編集対象外とし、フォーム上で `readonly` 属性により変更不可としなければならない（MUST NOT 受け入れる）。

保存成功時、システムは:

1. IndexedDB 上の対象レコード（同一 `id`）を新しいフィールド値で上書きしなければならない（SHALL）。
2. 地図上の対象 source／layer を、新しい属性（出典・minzoom／maxzoom）を反映した形で同一 id のまま再生成しなければならない（SHALL）。タイル URL は不変であり、ブラウザのタイルキャッシュからの再描画で済まなければならない（SHALL）。
3. 編集対象が編集時点で選択中であった場合、編集後も選択中の状態を維持しなければならない（SHALL）。

#### Scenario: 編集による名称変更が一覧ラベルに反映される

- **WHEN** ユーザーがカスタム背景地図 `OldName` を編集モードで開き、名称欄を `NewName` に変更して保存する
- **THEN** ラジオ一覧の当該行のラベルが `NewName` に更新されている。一覧上の表示順は変わらない

#### Scenario: 編集による出典変更が attribution に反映される

- **WHEN** ユーザーがカスタム背景地図を選択中の状態で、その地図を編集モードで開き、出典テキスト・出典リンク URL を変更して保存する
- **THEN** 地図右下の出典が、新しい入力値から組み立てられた文字列に更新されている

#### Scenario: 編集による minzoom／maxzoom 変更が地図に反映される

- **WHEN** ユーザーがカスタム背景地図を編集モードで開き、minzoom／maxzoom を変更して保存する
- **THEN** 当該背景地図を選択した状態でズーム操作を行った際、新しい minzoom／maxzoom の範囲に従ってタイルが描画される

#### Scenario: 編集モードでタイル URL は変更できない

- **WHEN** ユーザーが編集モードのフォームを開き、タイル URL 欄にフォーカスを当てるか値の変更を試みる
- **THEN** タイル URL 欄は `readonly` 属性により値が書き換えられない。フォーム送信時、保存されるレコードのタイル URL は編集前と完全に一致している

#### Scenario: 編集時にタイル再ダウンロードは発生しない

- **WHEN** ユーザーがカスタム背景地図の出典または minzoom／maxzoom のみを変更して保存し、その背景地図を表示し続ける
- **THEN** ブラウザのネットワークログに、保存直後の同じズーム・同じビューポートでのタイル URL に対する新規 HTTP リクエストが発生せず（同 URL がキャッシュから供給される）、視覚的なちらつきも発生しない

#### Scenario: 編集内容はリロード後も復元される

- **WHEN** ユーザーがカスタム背景地図を編集して保存し、ブラウザのタブを閉じてから同じオリジンを開き直す
- **THEN** ラジオ一覧の当該行のラベルおよび地図上の出典・zoom 範囲が編集後の値で表示される

### Requirement: カスタム背景地図の定義はブラウザの IndexedDB に永続化される

システムは、追加・編集されたカスタム背景地図の定義（名称・タイル URL・出典テキスト・出典リンク URL・minzoom／maxzoom・内部 ID）を、ブラウザの IndexedDB に永続化しなければならない（SHALL）。同一ブラウザで再度同じオリジンを開いた際、永続化された全カスタム背景地図が**最後の編集後の状態で**ラジオ一覧に復元されなければならない（SHALL）。

IndexedDB の読み込みに失敗した場合、システムはコンソール警告を出力したうえで、プリセットのみで起動を継続しなければならない（SHALL）。読み込み失敗を理由にアプリの初期化を中断してはならない（MUST NOT）。

#### Scenario: 追加した背景地図は再アクセス時にも一覧に存在する

- **WHEN** ユーザーがフォームからカスタム背景地図を 2 件追加し、ブラウザのタブを閉じてから同じオリジンを開き直す
- **THEN** 背景地図切替コントロールのラジオ一覧にプリセット 4 件と追加した 2 件、合計 6 件が表示される

#### Scenario: 削除した背景地図は再アクセス時にも復元されない

- **WHEN** ユーザーがカスタム背景地図を追加し、その後削除ボタンで削除してからブラウザのタブを閉じて開き直す
- **THEN** 削除した背景地図はラジオ一覧に表示されない

#### Scenario: IndexedDB 読み込み失敗時はプリセットのみで起動する

- **WHEN** IndexedDB の読み込みで例外が発生する状況下でページを読み込む
- **THEN** アプリは初期化を中断せず、ラジオ一覧にはプリセット 4 件のみが表示され、コンソールに警告が出力される

### Requirement: 最後に選択された背景地図はブラウザに永続化されリロード後に復元される

システムは、ユーザーが背景地図を切り替えるたびに、その時点で選択されているレイヤー ID（プリセット／ユーザー追加問わず）をブラウザに永続化しなければならない（SHALL）。ページ再読み込み時、システムはこの永続化された ID に対応する背景地図を選択状態として復元しなければならない（SHALL）。

永続化値が存在しない、または永続化値が指す背景地図が現存しない場合、システムは `osm-layer`（OSM）にフォールバックし、永続化値を `osm-layer` に上書きしなければならない（SHALL）。

#### Scenario: 最後に選択していたプリセットがリロード後も保持される

- **WHEN** ユーザーが背景地図を「航空写真」に切り替えてからページをリロードする
- **THEN** リロード後の初期表示で背景タイルが航空写真であり、ラジオの「航空写真」が選択状態（checked）になっている

#### Scenario: 最後に選択していたカスタム背景地図がリロード後も保持される

- **WHEN** ユーザーがカスタム背景地図を追加して選択し、ページをリロードする
- **THEN** リロード後の初期表示で背景タイルがそのカスタム背景地図であり、対応するラジオが選択状態になっている

#### Scenario: 永続化値が指すカスタム背景地図が削除済みの場合 OSM にフォールバックする

- **WHEN** カスタム背景地図を選択中の状態で、別タブから当該カスタムを削除する、もしくは IndexedDB の状態整合が崩れた状態でページを開く
- **THEN** ラジオの初期選択が `OSM` であり、背景タイルが OSM で表示され、以降の永続化値も `osm-layer` で上書きされる

#### Scenario: 永続化値が存在しない初回アクセスでは OSM が初期表示となる

- **WHEN** 当該オリジンに対する IndexedDB が空（初回アクセス）の状態でページを読み込む
- **THEN** ラジオの初期選択が `OSM` であり、背景タイルが OSM で表示される
