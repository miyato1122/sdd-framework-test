# 実機スモークチェックリスト — dependency-modernization

本書は依存パッケージ最新化（vite 8.0.13 / maplibre-gl 5.24.0 / @turf/distance 7.3.5 / maplibre-gl-opacity 1.8.0 / maplibre-gl-gsi-terrain 2.3.2）後に、防災ハザードマップ PWA の利用者可視機能（要件定義書 Requirement 3 の受け入れ基準 3.1〜3.8）が更新前後でリグレッションしていないことを実機で確認するためのチェックリストです。

## 役割分担（要件 4.2 対応）

- **目視判定は利用者が実施します。** 各項目の「期待される観測結果」が実機ブラウザで再現するか否かは、利用者がブラウザ画面を見て pass / fail を判定します。
- **実装側は本チェックリストと再現手順を提供する位置づけです。** 実装側は各機能に 1:1 対応する判定項目・再現手順・期待観測結果を整備するところまでを担い、実機の目視判定そのものは行いません（要件 4.2: 実装側がスモーク用チェックリストを提供し、目視判定は利用者が実施する）。
- 合格条件は「クリーン環境での build/dev/preview 成立（Requirement 2）」と「本チェックリスト全項目の pass（Requirement 3）」の双方の通過です（要件 4.1）。本書が扱うのは後者（実機スモーク）です。
- いずれかの項目が再現しない場合は不合格とし、「結果記録」欄に該当機能と原因を記録します（要件 4.3）。

## 前提（本書の責務外・参照のみ）

- **クリーン環境での build / dev / preview の準備・成立確認は本タスクの責務外です。**
  - クリーン環境（lockfile 再現）の確立は Task 1.2 の責務です。
  - クリーン環境での build/dev/preview 成立の検証は Task 3.1 の責務です。
  - 本書はこれらの手順を再掲・実装しません。実機スモークは、上記が成立した状態（dev または preview サーバが起動し、ブラウザコンソールにエラーが出ず初期地図が表示されている状態）を前提として開始します。
- 実機スモーク開始の前提状態（参照のみ。本書では実施しない）:
  - クリーン環境で `npm run build` が成果物を生成済み（Task 3.1 が確認）。
  - `npm run dev` または `npm run preview` で WebGL2 対応ブラウザに初期地図が表示され、コンソールエラーが無い（Task 3.1 が確認）。
- 位置情報を使う項目（3.3 / 3.4 / 3.6 / 3.7）は、ブラウザの位置情報許可と HTTPS もしくは `localhost` でのアクセスが必要です。dev/preview は `localhost` で提供されるため通常は満たされます。

## 連動集合に関する注記（3.4 / 3.6 / 3.7）

- 受け入れ基準 **3.4 / 3.6 / 3.7 は、`main.js` の同一の毎フレーム描画コールバック領域（`map.on('render', ...)` 内の現在地・経路ライン描画ロジック）に同居する連動集合**です。具体的には、現在地取得オフ時の現在地クリア（3.4）、ズーム閾値以上かつ現在地確定時の経路ライン描画（3.6）、ズーム閾値未満または現在地未確定時の経路ライン非表示（3.7）が、同一の render コールバック内の連続した分岐で処理されます。
- このため **3.4 / 3.6 / 3.7 は 1 グループとして連続して検証してください。** 個別に時間を空けて確認するのではなく、現在地取得を有効化した 1 セッション内でズーム操作と現在地取得トグルを連続して切り替え、3.6 → 3.7 → 3.4 の順に観測結果を一括で確認します。私的 API（`geolocationControl._watchState` / `nearestFeature._geometry`）の互換調整が行われた場合は、この 3 項目を必ず一括で再検証します。

## リグレッション比較の進め方（要件 4.4・参照のみ）

- 各項目の「結果記録」に、依存更新前の挙動（pre-upgrade baseline）と更新後の挙動（post-upgrade result）を記録し、利用者可視のリグレッションが無いことを確認します。
- 本書は記録枠を提供するのみで、runtime（実機での操作・観測）の実施そのものは利用者の目視判定（要件 4.2）に委ねます。
- 全 8 項目が pass、かつ「前提」に記載のクリーン環境 build/dev/preview（Task 1.2 / 3.1 の責務）が成立した場合に限り、実機スモークを合格とします（要件 4.1）。1 項目でも fail がある場合は不合格とし、該当機能・原因を記録します（要件 4.3）。私的 API（`_watchState` / `_geometry`）起因の回帰の場合は、公開 API フォールバック適用後に連動集合 3.4 / 3.6 / 3.7 を含む全項目を再検証した上で判定します。
