## タスク概要

「ローカルだけ通って lockfile 再現環境で落ちる」**偽 green 防止ゲート**。`node_modules` と `package-lock.json` を削除した完全クリーン状態から `npm install && npm run build` が exit 0 で完了することを確認し、再生成された `package-lock.json` をコミット対象に含める。

## 完了条件

- [ ] `rm -rf node_modules package-lock.json`（Windows では同等の削除）を実行済み
- [ ] `npm install` が exit 0 で完了
- [ ] 新規 `package-lock.json` が生成されている
- [ ] `npm run build` が exit 0 で完了
- [ ] `dist/` に成果物が生成されている
- [ ] `package-lock.json` が `git add` 可能な状態でステージされている（実コミットはユーザー判断）

## 主要実装項目

### クリーン環境の作成 🔵

**信頼性**: 🔵 *メモ [[project_001_false_green_build]] / REQ-002 より*

- Windows: `Remove-Item -Recurse -Force node_modules, package-lock.json`（ファイルロック発生時はリトライ、NFR-301）
- bash 環境: `rm -rf node_modules package-lock.json`

### 完全再現 install + build 🔵

**信頼性**: 🔵 *TC-REQ-002-01 より*

- `npm install` → exit 0 を確認
- `npm run build` → exit 0 を確認
- `dist/index.html` と `dist/assets/*` が生成されることを確認

### lockfile のステージング 🔵

**信頼性**: 🔵 *NFR-302 / TC-NFR-302-01 より*

- `git status` で `package.json` と `package-lock.json` がステージ可能であることを確認
- 実コミットはユーザー判断（本タスクは「コミット可能な状態にする」までを完了条件とする）

## 基本的なテスト要件

### 偽 green ゲート 🔵

**信頼性**: 🔵 *メモ [[project_001_false_green_build]] より*

- 失敗が再現したら**偽 green と判定**し、TASK-0002 のバージョン選定からやり直す（dataflow.md § 2.2 参照）
- 失敗の典型例:
  - `npm install` での `ERESOLVE`（lockfile 上限制約に阻まれて旧版が解決される）
  - build 時の ESM/CJS 解決失敗（Turf v7 と Vite 整合不良など）

## 注意事項

- **Windows ファイルロックの注意**: `node_modules` 削除中に EPERM が出た場合は数秒待って再試行（NFR-301）。VS Code や別ターミナルでファイルを掴んでいないか確認。
- **lockfile を残したまま install しない**: 「残したまま install」で通ると偽 green につながる。本タスクは**必ず lockfile 削除から開始**。
- **コミットは確認後**: `package-lock.json` の差分が大きいことが多いので、ユーザーが内容確認してから実コミットする。
