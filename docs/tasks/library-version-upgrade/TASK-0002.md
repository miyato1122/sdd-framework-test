## 主要実装項目

### 候補組み合わせの構築 🔵

**信頼性**: 🔵 *要件 REQ-001 / ヒアリング Q3 = (b) より*

- 各依存の最新版を `npm view <pkg> version` で取得し、`package.json` を書き換える
- `@turf/distance` は v7 系最新を採用（REQ-405、既存 default import を維持）

### 決定マトリクスに沿った install 試行 🔵

**信頼性**: 🔵 *architecture.md § バージョン選定戦略 / dataflow.md § 2.2 より*

1. `rm -rf node_modules package-lock.json` でクリーン化
2. `npm install` を実行
3. `ERESOLVE` / peer dep エラーが出たら、衝突中心パッケージ（プラグイン優先）を一段戻して再試行
4. 成功するまで反復

### build 試行 🔵

**信頼性**: 🔵 *要件 REQ-003 / NFR-302 より*

- `npm run build` を実行
- 失敗した場合は失敗版を一段戻して install からやり直し（dataflow.md § 2.2）

### runtime 初期ロード確認 🔵

**信頼性**: 🔵 *要件 EDGE-001 / ヒアリング Q4 = (a) より*

- `npm run dev` を起動しブラウザで開く
- ブラウザコンソールに `useGsiTerrainSource`/`addProtocol`/プラグイン由来の runtime エラーが出ないことを確認
- エラーが出る場合は `maplibre-gl` を一段戻して install からやり直し（Q4 = a）

### 採用版と判断記録 🔵

**信頼性**: 🔵 *REQ-302 / ヒアリング Q4 より*

- 採用組み合わせ（バージョン番号）を本ファイル末尾または `notes.md` に記録
- 一段戻しが発生した場合、その対象パッケージと理由を明記

## 注意事項

- **クリーン化必須**: `package-lock.json` を残したまま `npm install` のみで更新すると、上限制約により最新版に到達しないことがある（EDGE-102）。必ず lockfile を削除してから install。
- **Windows ファイルロック**: install 中の EPERM/EBUSY は許容、リトライ（NFR-301）。
- **Turf v7 default import**: `import distance from '@turf/distance'` の形式は維持（REQ-405、既存 main.js 行10）。
- **本タスクでは `_watchState` には触らない**: REQ-501 の書き換えは TASK-0004 に集約。本タスクは依存解決と build/runtime 確認に集中。
