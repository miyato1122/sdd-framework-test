## タスク概要

TASK-0001 で記録したベースライン値と更新後値を比較し、非機能要件（パフォーマンス・セキュリティ）が**退化していない**ことを確認する。閾値はいずれも「現行比 2 倍を超えない」「現行比退化なし」の緩いゲートで、SDD 演習目的に合わせた最小限の検証。

## 依存タスク

- **前提タスク**: [TASK-0006](TASK-0006.md)（クリーン環境再現後の正確な更新後値を計測するため）
- **後続タスク**: なし（最終タスク）

## 完了条件

- [ ] `npm run dev` のコールドスタート時間（更新後）が記録され、ベースライン比 2 倍を超えていない
- [ ] `dist/` 合計サイズ（更新後）が記録され、ベースライン比 2 倍を超えていない
- [ ] `npm audit --omit=dev` の high / critical 件数（更新後）が記録され、ベースライン比で増加していない
- [ ] 上記 3 つの比較表が `docs/tasks/library-version-upgrade/verify-log.md` または overview 等に追記されている

## 主要実装項目

### dev コールドスタート計測（更新後） 🔵

**信頼性**: 🔵 *TC-NFR-001-01 より、TASK-0001 と同手順*

- 手順: `rm -rf node_modules/.vite` → `npm run dev`、3 回試行の中央値
- 閾値: ベースライン × 2 を超えない（NFR-001）

### build 成果物サイズ計測（更新後） 🔵

**信頼性**: 🔵 *TC-NFR-002-01 より、TASK-0001 と同手順*

- 手順: `npm run build` → `dist/` 合計サイズ
- 閾値: ベースライン × 2 を超えない（NFR-002）

### npm audit 比較 🟡

**信頼性**: 🟡 *NFR-101 の閾値「現行より増加しない」だが、レジストリ側 advisory の追加で増加する可能性があり実測ばらつきを許容*

- 手順: `npm audit --omit=dev --json` から high / critical を抽出
- 閾値: ベースラインから増加していない
- 増加した場合: 増加件数と原因パッケージを記録。新規 advisory が原因なら本要件の責任外（後続要件で対処）

## 注意事項

- **計測条件の統一**: コールドスタートとサイズは TASK-0001 と同じマシン・同じ OS 状態で計測すること（CPU 使用状況や他プロセスの影響を排除）。
- **npm audit のばらつき許容**: レジストリ側で新規 advisory が追加された場合、本要件の責任外。差分の原因をログに記録し、必要なら別タスク（次の依存更新サイクル）に送る。
- **実測値の保存**: ベースライン（TASK-0001）と更新後（本タスク）の生計測値も保存しておくと、次回更新時の比較に再利用できる。
