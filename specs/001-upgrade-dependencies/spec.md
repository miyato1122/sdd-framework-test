# 機能仕様: 依存ライブラリの最新化（package.json）

**Feature Branch**: `001-upgrade-dependencies`
**Created**: 2026-05-18
**Status**: Draft
**Input**: ユーザー記述: 「package.jsonの各ライブラリが古いので、動作する最新バージョンに上げたい。」

> 言語方針: 本仕様は憲章 v1.1.0「成果物の言語」制約に従い日本語で記述する。
> パッケージ名・コマンド・API 名など技術的に英語が必須の要素は原文のまま用いる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 既存機能が回帰しない (Priority: P1)

地図アプリの利用者は、ライブラリ最新化の前後で体験が変わらないことを期待する。
地図の初期表示、背景地図の切り替え、地形表示・不透明度調整、距離計測など、
現行アプリが提供する既存機能が、アップグレード後も同じ操作・同じ結果で動作する。

**Why this priority**: 最新化作業の唯一にして最重要の受け入れ条件は「壊れていない
こと」。これ単体で「最新化しても機能が維持されている」という検証価値が成立し、
最小実用成果（MVP）となる。

**Independent Test**: アップグレード後のビルドを起動し、既存機能を一通り手動
スモークして、アップグレード前と同じ挙動・表示になることを確認できる。

**Acceptance Scenarios**:

1. **Given** 依存を最新化したビルド, **When** アプリを起動して地図を表示する,
   **Then** アップグレード前と同じ初期地図が表示される
2. **Given** アプリ起動済み, **When** 背景地図を切り替える,
   **Then** アップグレード前と同じ背景地図が同じ操作で切り替わる
3. **Given** アプリ起動済み, **When** 地形表示・不透明度・距離計測などの既存機能を操作する,
   **Then** いずれもアップグレード前と同等に動作し、コンソールに新規エラーが出ない

---

### User Story 2 - サポート対象の最新環境で開発・ビルドできる (Priority: P2)

保守者は、サポートが継続している最新のライブラリ群と、それに対応する Node
バージョンで、ローカル開発と本番ビルドを問題なく行える。

**Why this priority**: 保守性・セキュリティ・将来の機能追加（例: README #4 の
Nuxt 移行）の土台となる。回帰がない（US1）ことを前提として価値を持つため P2。

**Independent Test**: 規定の Node バージョンのクリーン環境で `npm install` →
`npm run build` および `npm run dev` が追加手修正なしで成功することを確認できる。

**Acceptance Scenarios**:

1. **Given** 規定 Node バージョンのクリーン環境, **When** `npm install` を実行する,
   **Then** 依存解決が成功し、未解決の peer/競合エラーが残らない
2. **Given** 依存導入済み, **When** `npm run build` を実行する,
   **Then** ビルドが成功し成果物が生成される
3. **Given** 依存導入済み, **When** `npm run dev` を実行する,
   **Then** 開発サーバが起動し地図が表示される

---

### User Story 3 - SDD フレームワーク比較の記録が残る (Priority: P3)

演習の評価者は、本題材（ライブラリ最新化）を Spec Kit（git-spec）で実施した
結果を、他フレームワークの試行と比較できる形で参照できる。

**Why this priority**: 本リポジトリの目的は SDD フレームワーク比較演習であり、
記録がなければ演習価値が出ない。ただしアプリ動作（US1/US2）とは独立し、
成果物への影響が限定的なため P3。

**Independent Test**: README の「検討結果 > git-spec」節に本実行の結果（手順・
遭遇した破壊的変更・所要・課題）が日本語で記載されていることを確認できる。

**Acceptance Scenarios**:

1. **Given** 最新化作業が完了している, **When** README の検討結果を参照する,
   **Then** git-spec 節に本実行の記録が他フレームワーク欄と比較可能な粒度で存在する

---

### Edge Cases

- `maplibre-gl` のメジャーアップで `main.js` が用いる API（マップ生成・コントロール・
  イベント・`maplibre-gl-opacity` / `maplibre-gl-gsi-terrain` との連携）が破壊的に
  変更された場合、機能等価を保つ修正が必要になる
- `maplibre-gl-gsi-terrain`（現状 `0.0.2`）が最新 `maplibre-gl` と非互換、または
  メンテナンス停止の場合、互換最新版への据え置きか機能等価な代替が必要になる
- `vite` 3→8 のメジャーアップで `--base=./` を含むビルド設定や Node 要件が
  変わり、ローカル/CI 環境に影響する場合
- `package-lock.json` と推移的依存の競合・不整合が発生する場合
- 最低 Node バージョン引き上げにより、既存開発者環境や README「動作要件」と
  齟齬が出る場合
- 既知の高～重大脆弱性が、対応版の不在により最新化後も残存する場合

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは package.json の全依存（`vite`, `maplibre-gl`,
  `@turf/distance`, `maplibre-gl-opacity`, `maplibre-gl-gsi-terrain`）を、相互に
  動作する最新の安定版へ更新しなければならない（メジャーアップを含む）
- **FR-002**: 更新後、`npm run build` が成功しなければならない
- **FR-003**: 更新後、`npm run dev` で開発サーバが起動し地図が表示されなければ
  ならない
- **FR-004**: 既存機能（地図初期表示、背景地図切替、地形表示・不透明度、距離
  計測など現行アプリが提供する全機能）がアップグレード前と同等に動作し、回帰が
  あってはならない
- **FR-005**: 破壊的変更が生じた箇所は、機能等価を維持するようコードを修正
  しなければならない
- **FR-006**: ある依存が最新 `maplibre-gl` と互換でない、またはメンテナンス
  終了の場合、(a) 互換最新版へ据え置く、または (b) 機能等価の代替へ置換する
  のいずれかを行い、その判断と根拠を記録しなければならない
- **FR-007**: 最終的に採用した Node バージョン要件を、package.json と README
  「動作要件」で一致させなければならない
- **FR-008**: 依存解決は `package-lock.json` により再現可能でなければならない
- **FR-009**: 既知の高～重大脆弱性を持つバージョンを残してはならない。技術的に
  解消できない場合は、残存理由を記録しなければならない
- **FR-010**: 本実行の結果（実施手順・遭遇した破壊的変更・所要・課題）を
  README の「検討結果 > git-spec」節に日本語で記録しなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者が確認できる既存地図機能（初期表示・背景切替・地形/不透明度・
  距離計測）の 100% が、アップグレード前と同じ結果になる（手動スモーク全項目 PASS、
  新規コンソールエラー 0 件）
- **SC-002**: 規定 Node バージョンのクリーン環境で、依存インストールから本番
  ビルド完了までが追加の手修正なしで成功する
- **SC-003**: 既知の高～重大脆弱性の件数が 0、または残存する各件に文書化された
  正当化がある
- **SC-004**: package.json・package-lock.json・README「動作要件」・README「検討
  結果」の相互不整合が 0 件
- **SC-005**: 本題材を Spec Kit で実施した記録が README に残り、他フレームワーク
  欄と比較可能な粒度（手順・破壊的変更・所要・課題）で記載されている

## Assumptions

- 本実行は SDD フレームワーク比較演習における「git-spec / Spec Kit」のデータ
  ポイントである（ユーザー回答 Q1: A）。README の「ライブラリのバージョンアップ
  （2026-05-14 完了）」は別フレームワーク試行の記録とみなし、本実行はそれを
  上書きせず、「検討結果」セクションに Spec Kit 分を追記する。
- 「動作する最新バージョン」は、メジャーアップを含む相互に整合する最新安定版を
  指す（ユーザー回答 Q2: A）。プレリリース／RC 版は対象外。
- 現状、自動テストスイートは存在しないため、回帰検証は「ビルド成功＋手動スモーク」
  （憲章 II の手動スモーク手順）で行う。最小限の回帰テスト追加の要否は plan
  フェーズで検討する。
- 対象アプリの機能範囲は、現行 `main.js` / `index.html` / `style.css` が提供する
  ものに限定する。新機能追加は本仕様のスコープ外。
- ネットワーク経由のタイル／地形データ提供元（GSI 等）は引き続き利用可能とする。
- ターゲット Node は README 記載の `^20.19.0 || >=22.12.0`（Vite 8 要件）を基準と
  しつつ、最終的に採用するツール最新版の要件に合わせて確定する。
- README #4「Nuxt 構成への移行」は別タスクであり、本仕様のスコープ外。
