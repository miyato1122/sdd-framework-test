# Feature Specification: ユーザー定義のオリジナル背景地図の追加

**Feature Branch**: `003-custom-basemap`  
**Created**: 2026-05-18  
**Status**: Draft  
**Input**: User description: "背景地図にユーザーがオリジナルの背景地図を追加できる機能を追加実装したい。イメージとして、背景地図一覧の最後尾に追加ボタンがあり、そこを押すと背景地図追加フォームが表示され、必要な情報を入力します。"

## Clarifications

### Session 2026-05-18

- Q: ユーザーが入力する「地図タイルの取得元」の最小必須定義は？ → A: URL テンプレート（タイル座標の差し込み箇所を含む）のみ必須。タイル方式は標準 XYZ 固定、ズーム範囲はアプリ側の既定値を適用
- Q: タイル取得元 URL の妥当性検証ルール（FR-008 の「不正」の定義）は？ → A: 形式チェック（URL として解釈可能かつタイル座標の差し込み箇所を含む）＋スキーム制限（`http(s)` のみ許可し `javascript:`/`data:` 等を排除）。混在コンテンツ(http)は許可するが利用者責任
- Q: 追加した背景地図の一意性・識別ルールは？ → A: 同名禁止。表示名を一意キーとし、組み込み4種を含む既存の背景地図と同じ表示名での追加は不正として拒否する
- Q: 追加成功後、その背景地図を自動選択・表示するか？ → A: 自動選択しない。一覧に追加されるのみで表示中の背景地図・出典・現在選択は変わらず、利用者が明示的に選択して初めて切り替わる
- Q: 出典の入力方法（生 HTML を許容するか）は？ → A: 生 HTML は受け付けない（セキュリティ）。出典は「表示名（必須・プレーンテキスト）」と「リンク URL（任意・`http(s)` のみ）」に分離して入力させ、システムが HTML エスケープして安全な出典表記を構築する。これにより出典が描画される AttributionControl（`innerHTML` 描画）への HTML/スクリプトインジェクションを構造的に防止する

### User Story 1 - オリジナル背景地図を追加して表示できる (Priority: P1)

地図を閲覧しているユーザーが、背景地図切替コントロール（002 で実装済み）の一覧最後尾にある「背景地図を追加」操作を押すと、背景地図追加フォームが表示される。ユーザーは表示名・地図タイルの取得元・出典の表示名（任意で出典リンク URL）など必要情報を入力して確定すると、入力した内容のオリジナル背景地図が一覧に追加され、それを選ぶと地図の背景がそのユーザー定義地図へ切り替わる。組み込みの4種（OSM／地理院地図／航空写真／白地図）では足りない地図を、ユーザー自身が持ち込んで使えるようになる。

**Why this priority**: 本フィーチャーの中核価値そのもの。これ単体で「ユーザーが自分の背景地図を追加して表示する」という利用価値が成立し、最小限の出荷可能機能（MVP）になる。002 への増分拡張の主目的を満たす。

**Independent Test**: 地図表示後、一覧最後尾の追加操作を押してフォームを開き、表示名・タイル取得元・出典の表示名（任意でリンク URL）を入力して確定し、追加された項目を選択すると地図背景がその取得元の地図に変化することを目視で確認できる。他のストーリーが未実装でも単独で検証可能。

**Acceptance Scenarios**:

1. **Given** 地図が表示され切替コントロールに組み込み4種が並んでいる, **When** ユーザーが一覧最後尾の「背景地図を追加」操作を押す, **Then** 背景地図追加フォームが表示される
2. **Given** 追加フォームが表示されている, **When** ユーザーが表示名・地図タイルの取得元・出典の表示名（任意で出典リンク URL）を入力して確定する, **Then** 入力内容のユーザー定義背景地図が一覧に追加され選択可能になる。ただし表示中の背景地図・出典・現在選択は変わらない（自動選択しない）
3. **Given** ユーザー定義背景地図が一覧に追加されている, **When** ユーザーがそれを選択する, **Then** 地図の背景が入力した取得元の地図へ切り替わり、コントロール上の現在選択がそのユーザー定義背景地図を示す

---

### User Story 2 - 追加した背景地図が組み込み4種と一貫して切替・出典表示される (Priority: P2)

ユーザーが追加した背景地図は、002 の組み込み背景地図とまったく同じ操作感で選択でき、切替コントロールは現在どれを選んでいるかを示す。ユーザー定義背景地図を選択中は、ユーザーが入力した出典（クレジット）が地図上に表示され、組み込みの背景地図へ切り替えると出典もその提供元に対応した内容へ自動的に戻る。002 の出典自動切替の仕組み（OSM／国土地理院の出典）と矛盾なく統合される。

**Why this priority**: 各データ提供元の利用規約は出典表示を求めるため、追加した地図と出典の不整合・出典の取り違えはコンプライアンス上の問題となり得る。US1 の上に積み上がる必須の整合性価値であり、「002 との関係・差分」を仕様で担保する中核。US1 と分離して独立にテスト可能。

**Independent Test**: ユーザー定義背景地図を1つ追加した状態で、ユーザー定義 → 組み込み → ユーザー定義 と相互に切り替え、そのつど画面上の出典表記が選択中の背景地図に対応した内容（ユーザー定義時はユーザー入力の出典、組み込み時は 002 の対応出典）へ更新され、現在選択表示が正しく追従することを確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザー定義背景地図を表示中, **When** ユーザーが組み込みの「地理院地図（標準地図）」へ切り替える, **Then** 出典表記が国土地理院由来の表記へ更新され、現在選択が「地理院地図（標準地図）」を示す
2. **Given** 組み込みの「OSM」を表示中, **When** ユーザーが追加したユーザー定義背景地図へ切り替える, **Then** 出典表記がそのユーザー定義背景地図に入力された出典へ更新される
3. **Given** ユーザー定義背景地図を表示中, **When** ユーザーが出典表記を確認する, **Then** 入力した出典文言が読み取れる形で表示されている

---

### User Story 3 - 不足・不正な入力を利用者に分かる形で拒否する (Priority: P3)

ユーザーが追加フォームで必須情報を入力しないまま確定した場合、タイル取得元が不正（URL として解釈不能／タイル座標の差し込み箇所を欠く／`http(s)` 以外のスキーム）の場合、出典リンク URL を入力したのに不正（URL として解釈不能／`http(s)` 以外のスキーム）の場合、または表示名が既存の背景地図と重複する場合、システムは背景地図を追加せず、何が不足・不正かを利用者が分かる形で提示する。失敗が無言で握りつぶされたり、壊れた背景地図が一覧に紛れ込んだりしない。利用者は追加を取りやめて元の地図表示へ戻ることもできる。

**Why this priority**: 入力検証は利用品質・信頼性として重要だが、US1/US2 が成立した上での仕上げに当たるため P3。追加機能を安心して使えるようにするガード。

**Independent Test**: 必須項目を空にして確定、または明らかに不正なタイル取得元を入力して確定し、背景地図が追加されず利用者に不足／不正が提示されること、キャンセル操作で元の地図表示・切替コントロールへ戻れることを確認できる。

**Acceptance Scenarios**:

1. **Given** 追加フォームが表示されている, **When** 必須項目（表示名・タイル取得元・出典の表示名）の一部を空のまま確定する, **Then** 背景地図は追加されず、不足している項目が利用者に提示される（出典リンク URL は任意のため空でも不足扱いにしない）
2. **Given** 追加フォームが表示されている, **When** タイル取得元に不正な値（URL として解釈不能／タイル座標の差し込み箇所を欠く／`http(s)` 以外のスキーム）を入力して確定する, **Then** 壊れた背景地図は一覧に追加されず、利用者が問題を認識できる
3. **Given** 追加フォームが表示されている, **When** 出典リンク URL に不正な値（URL として解釈不能／`http(s)` 以外のスキーム）を入力して確定する, **Then** 背景地図は追加されず、出典リンク URL の不正が利用者に提示される
4. **Given** 追加フォームが表示されている, **When** 既存の背景地図（組み込み4種または追加済み）と同じ表示名を入力して確定する, **Then** 背景地図は追加されず、表示名が重複している旨が利用者に提示される
5. **Given** 追加フォームが表示されている, **When** 出典の表示名に HTML（`<script>` 等）を含めて確定する, **Then** その文字列はリンク／スクリプトとして解釈されず、エスケープされたテキストとして安全に出典表示される（HTML インジェクション不可）
6. **Given** 追加フォームが表示されている, **When** ユーザーが追加を取りやめる（キャンセル）, **Then** 一覧・地図表示・出典は変化せず、元の切替コントロールへ戻る

---

### Edge Cases

<!--
  ACTION REQUIRED: The content in this section represents placeholders.
  Fill them out with the right edge cases.
-->

- 必須項目（表示名／タイル取得元／出典の表示名）が未入力のまま確定したとき、追加されず不足項目が利用者に提示されること（出典リンク URL は任意＝空でも不足扱いにしない）
- 出典リンク URL を入力したのに不正（URL として解釈不能／`http(s)` 以外のスキーム）のとき、追加されず利用者が問題を認識できること
- 出典の表示名に HTML 特殊文字やタグ（`<script>` 等）を含めても、リンク／スクリプトとして実行されずエスケープ済みテキストとして表示されること（生 HTML 非受理＝HTML インジェクション不可）
- タイル取得元が不正（URL として解釈不能／タイル座標の差し込み箇所を欠く／`http(s)` 以外のスキーム）のとき、壊れた背景地図が無言で一覧に入らないこと
- 追加したユーザー定義背景地図のタイル提供元が不通・拒否（一時障害等）のとき、地図の基本操作（ズーム・パン）は継続でき、失敗が無言で握りつぶされず利用者が状況を認識できること
- 組み込み背景地図を表示中に追加フォームを開いて取りやめたとき、表示中の背景地図・出典・現在選択が一切変化しないこと
- 追加直後にそのユーザー定義背景地図を選択したとき、追加と選択の間で状態不整合（背景と出典のズレ等）が発生しないこと
- ページを再読込したとき、追加したユーザー定義背景地図は失われ、既定（OSM）に戻ること（永続化しない前提の明示）
- 既存（組み込み4種または追加済み）と同じ表示名で追加しようとしたとき、追加されず重複である旨が利用者に提示されること
- 追加数が多い場合でも、利用者が一覧上でどれを現在選択しているか（一意な表示名で）識別できること
- 追加フォーム表示中に地図を操作しても、地図やアプリ全体が操作不能・フリーズに陥らないこと
- 狭幅／モバイル画面で、追加操作・追加フォーム・出典表記が既存の地図コントロールや出典表記と重なって操作不能にならないこと（002 と一貫）

### Functional Requirements

- **FR-001**: システムは 002 の背景地図切替コントロールの一覧最後尾に「背景地図を追加」操作（追加ボタン）を常時表示しなければならない
- **FR-002**: 利用者が「背景地図を追加」操作を行うと、システムは背景地図追加フォームを表示しなければならない
- **FR-003**: 背景地図追加フォームは「表示名（ラベル）」「地図タイルの取得元（タイル座標の差し込み箇所を含む URL テンプレート）」「出典の表示名（必須・プレーンテキスト）」「出典リンク URL（任意・`http(s)`）」を利用者が入力できなければならない。出典は生 HTML として入力させてはならず、システムが出典の表示名を HTML エスケープし、リンク URL があれば安全なリンクとして出典表記を構築する。タイル方式は標準 XYZ 固定とし、ズーム範囲はシステム既定値を適用する（利用者は方式・ズーム範囲を入力しない）
- **FR-004**: 利用者が必要情報を入力して確定すると、システムは入力内容に基づくユーザー定義背景地図を背景地図一覧に追加しなければならない。追加のみでは表示中の背景地図・出典・現在選択を変更してはならず、利用者が当該地図を明示的に選択して初めて切り替わる
- **FR-005**: 追加されたユーザー定義背景地図は、組み込み背景地図（OSM／地理院地図／航空写真／白地図）と同じ操作で選択でき、選択するとその取得元の地図が背景として表示されなければならない（002 の切替挙動に準拠）
- **FR-006**: ユーザー定義背景地図を選択中は利用者が入力した出典表記を 002 と同じ仕組みで地図上に表示し、他の背景地図へ切り替えた際は切替先の背景地図に対応した出典へ自動的に切り替わらなければならない（002 の出典自動切替と一貫）
- **FR-007**: 切替コントロールは、ユーザー定義背景地図についても現在選択中であることを利用者が識別できる状態表示を持たなければならない（002 の現在選択表示と一貫）
- **FR-008**: 背景地図追加フォームは、必須項目（表示名・タイル取得元・出典の表示名）が未入力、タイル取得元が「URL として解釈できない／タイル座標の差し込み箇所を含まない／`http(s)` 以外のスキーム（`javascript:`・`data:` 等）」のいずれかに該当、出典リンク URL が入力されているのに「URL として解釈できない／`http(s)` 以外のスキーム」のいずれかに該当、または表示名が既存の背景地図（組み込み4種および追加済みのユーザー定義背景地図）と重複する場合、背景地図を追加せず、何が不足・不正かを利用者が分かる形で提示しなければならない（無言で失敗しない）。出典リンク URL は任意であり、未入力の場合は出典の表示名のみ（リンクなし）で表記を構築する。混在コンテンツ（`https` ページ上の `http` タイル）はスキーム上は許可するが、その結果生じる取得失敗は利用者責任とし FR-010 の扱いに従う
- **FR-009**: 背景地図追加フォームは、利用者が追加を取りやめて元の地図表示・切替コントロールへ戻れる手段（キャンセル）を提供しなければならない
- **FR-010**: ユーザー定義背景地図のタイル取得に失敗した場合でも、地図の基本操作（ズーム・パン）は継続でき、失敗が無言で握りつぶされず利用者が状況を認識できなければならない（002 のタイル取得失敗時要件と一貫）
- **FR-011**: 既存の組み込み背景地図に関する挙動（4種の選択・初回／再読込時の既定 OSM・出典の自動表示と切替）は、本機能の追加によって変化してはならない（002 の機能要件を回帰させてはならない）
- **FR-012**: 背景地図追加フォームの表示中・操作中も、地図およびアプリ全体が操作不能・フリーズに陥ってはならない

### Key Entities *(include if feature involves data)*

- **ユーザー定義背景地図**: 利用者が追加する背景地図。属性＝表示名（ラベル）・地図タイルの取得元・出典の表示名・出典リンク URL（任意）。**表示名は全背景地図（組み込み4種＋追加済みユーザー定義）を通じて一意**であり、現在選択の識別はこの一意な表示名で行う。002 の「背景地図（ベースマップ）」エンティティの新たな種別として一覧に加わり、組み込み種別と同じく切替対象・出典対象となる。組み込み4種との違いは「提供元情報を利用者が入力で持ち込む」点
- **背景地図追加フォーム**: 「背景地図を追加」操作から開く入力UI。属性＝入力項目（表示名・タイル取得元・出典の表示名・出典リンク URL〔任意〕）・検証結果（不足／不正の項目別指摘）・確定／取消の操作
- **追加ボタン（追加アフォーダンス）**: 002 の切替コントロールの一覧最後尾に常時表示され、背景地図追加フォームを開く操作要素
- **出典表記（クレジット）**: 002 から継承するエンティティ。ユーザー定義背景地図に対しては、利用者入力の「出典の表示名（HTML エスケープ）」と任意の「出典リンク URL（`http(s)` 検証済み）」から**システムが安全に構築した HTML** を用いる（利用者の生 HTML は受理しない）。背景地図と1対1で対応し、現在の選択に追従して表示が切り替わる

### Measurable Outcomes

- **SC-001**: 利用者は外部手順なしに、一覧最後尾の追加操作からフォームを開き、必要情報を入力して新しい背景地図を追加・表示するまでを2分以内に完了できる
- **SC-002**: 追加した背景地図と組み込み背景地図を相互に切り替えたとき、いずれの状態でも対応する正しい出典が画面に表示される（追加×組み込みの双方向で出典と提供元が一致する割合 100%）
- **SC-003**: 追加機能の利用前後で、組み込み4種の切替・初回／再読込時の既定 OSM・出典自動表示の挙動に差異が生じない（002 の受け入れシナリオを 100% 維持＝既存挙動の回帰ゼロ）
