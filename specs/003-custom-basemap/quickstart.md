# クイックスタート（Phase 1）: ユーザー定義のオリジナル背景地図の追加

002 の手動スモークに **003 の追加・検証・回帰確認**を上乗せした検証手順。描画/コントロール/a11y 経路はユニット化不可のため本書で手動確認する（憲章 II）。

## 0. 環境・品質ゲート（クリーン環境で必須）

> 過去知見: lockfile 再現環境での「ビルド成功/テスト PASS」偽green を回避するため、**クリーンインストール環境**で実行・確認すること（主張はクリーン環境再検証必須）。Windows の file-lock 事象時は `npm install` を優先。

1. `npm install`（`package-lock.json` 不変＝新規依存ゼロを確認。`maplibre-gl-opacity` 等の既存依存のみ）。
2. `npm run test` … `basemaps.js` の純粋ロジック（002 既存＋003 検証/生成）が `node --test` で全 PASS。
3. `npm run build` … 成功（必須ゲート・憲章 II）。
4. `npm run dev` で起動し以下を実施。

## 1. 既定・回帰確認（FR-011／SC-003：002 挙動が不変）

1. 初回表示で背景=OSM、左下に背景スイッチャー、組み込み4種（OSM/地理院地図/航空写真/白地図）が並ぶ。
2. 4種を順に選択 → 背景が即時切替、出典が提供元へ自動追従（OSM=OpenStreetMap、GSI=地理院タイル）。
3. ハザード（左上）・skhb（右上）・地形/現在地（右下）の各コントロールが従来どおり動作（自作スイッチャー化の副作用なし）。
4. ページ再読込で背景=OSM に戻る。
5. → 1〜4 が 002 と差異なし＝回帰ゼロ（SC-003 100%）。

## 2. 追加フロー（US1・FR-001/002/003/004、Q4）

1. スイッチャー一覧の**末尾に「＋ 背景地図を追加」**がある（FR-001）。押すとインラインの追加フォームが開く（FR-002）。フォーム表示中も地図のズーム/パンが効く（FR-012）。
2. 表示名・タイル取得元（例: 任意の公開 XYZ `https://.../{z}/{x}/{y}.png`）・出典の表示名（必須）・出典リンク URL（任意）を入力し確定。
3. 一覧末尾（「追加」ボタンの直前）に当該エントリが増える。**ただし表示中の背景・出典・現在選択は変わらない**（自動選択しない＝Q4）。
4. 追加したエントリを選択 → 背景がその取得元へ切替、出典が「出典の表示名」（リンク URL を入れた場合はクリック可能なリンク）として更新（US1-AC3／FR-005）。生 HTML ではなくシステムが安全構築（Q5）。
5. 組み込みへ戻す → 出典が提供元出典へ自動復帰（US2／FR-006）。ユーザー定義↔組み込みを相互に往復し双方向で出典一致（SC-002）。

## 3. 検証・異常系（US3・FR-008/009、SC-004）

1. 必須項目（表示名/取得元/**出典の表示名**）を空で確定 → 追加されず、**不足項目が項目別に提示**される。**出典リンク URL は任意**＝空でも不足扱いにならないことを確認。
2. 取得元に不正値で確定し、各々追加されず理由提示:
   - URL として解釈不能な文字列
   - `{z}{x}{y}` のいずれかを欠く URL
   - `javascript:` / `data:` 等 `http(s)` 以外スキーム
3. 出典リンク URL に不正値（URL 解釈不能／`javascript:` 等 非 http(s)）を入力して確定 → 追加されず「出典リンク URL」項目に理由提示（Q5）。
4. 既存（組み込み4種 or 追加済み）と**同じ表示名**で確定 → 追加されず「重複」提示（Q3）。
5. **セキュリティ（Q5）**: 出典の表示名に `<script>alert(1)</script>` や `<img src=x onerror=alert(1)>` を入れて追加・選択 → アラートは出ず、出典欄に**エスケープされた文字列がそのままテキスト表示**される（HTML/スクリプトとして実行されない）。
6. 混在コンテンツ（`https` ページで `http://.../{z}/{x}/{y}.png`）→ 追加は通る（スキーム OK）。タイル取得失敗時は §5 の通知が出る。
7. キャンセル → 一覧・地図・出典・現在選択は不変、フォームが閉じ元の表示へ戻る（US3-AC6）。
8. → 無言で成功扱いが 0%（SC-004）。

## 4. アクセシビリティ（憲章 III・**実機確認必須**）

> 過去知見: 002 で `label[for]` 根拠の静的断定が実機 NG。静的に断定せず必ず目視/操作で確認する。

1. キーボードのみで: 追加ボタンへ到達・起動、フォーム各入力へ Tab 移動、確定/キャンセル操作ができる。
2. ラジオはキーボードで選択切替でき、**ラベルクリックでも対応ラジオが切り替わる**（`label[for]` 実挙動）。
3. フォーカス順が論理的、コントラストが可読。新規 UI 追加で組み込み4種の操作 a11y が後退していない。

## 5. タイル取得失敗（FR-010・SC-005、002 R5 再利用）

1. 到達不能/403 になる取得元のユーザー定義背景を選択 → 画面に控えめな失敗通知（`.map-error-toast`）が出る。
2. その間も地図のズーム/パンは継続でき、現在選択は不変、無言で壊れない。
