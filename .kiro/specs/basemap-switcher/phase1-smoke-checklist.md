# Phase 1 実機スモークチェックリスト — basemap-switcher（第2段）

本書は **basemap-switcher 第2段 Phase 1（タスク 6.1〜9.1 完了状態）** の受け入れ基準に対応した**ブラウザ実機目視**のチェックリストです。tech.md／プロジェクト方針により UI・ライブラリ挙動は静的解析で断定せず、**実機目視はユーザーが実施**します（実装側 = 本チェックリスト提供＋自動検証可能範囲 = task 10.1 のクリーン環境健全性まで完了済み）。

第2段は Phase 0（受け入れ済み）を**非回帰ベースライン**として保持しつつ、カスタム背景地図の追加・選択・出典追従・定義永続化を導入したものです。Phase 2（編集／削除／選択状態の永続化＋復元）は未着手のため、本チェックリストでは Phase 2 で初めて観測される挙動は対象外とします（明示）。

## 前提・起動手順

- クリーン環境健全性（install/build/dev/preview）は task 10.1 で確認済み（Windows 環境特性により `npm ci` 不可・`npm install` lockfile 整合を正準）。
- 実機確認はモダンブラウザ（WebGL2／ネイティブ `<dialog>` 対応）で実施。
- 起動: リポジトリルートで `npm run dev`（または `npm run build` 後 `npm run preview`）→ 表示された `http://localhost:<port>/` を開く。
- 各項目の判定欄に PASS / FAIL（FAIL は所見を併記）を記入。1 件でも FAIL があれば実装へ差し戻し。
- Phase 2 で観測される挙動（Req 1.6 改訂結線・編集／削除・選択復元）は本書スコープ外（Phase 2 完了後の 14.2 にて確認）。

## 2. Phase 1 新規挙動: 出典の安全な構築（Req 3.5／4.1〜4.5）

- [ ] 4.x 組込み 4 種の出典 DOM（DevTools で右下出典欄の HTML を確認）に**未エスケープ markup や `javascript:` リンクが含まれない**。`<a>` の `href` は `https://` で `target="_blank"` `rel="noopener"` が付与されている。Phase 0 と意味的に等価（リンク先・テキスト・ターゲット属性が同じ）。
- [ ] 4.5 後述「カスタム背景地図の追加」項で `label` に意図的な markup を含む値（例: `<img src=x onerror=alert(1)>`）を入力して保存。一覧に表示される表示名は**テキストとして実体参照化されて表示**され、`alert` は発火しない。
- [ ] 4.4 後述「カスタム背景地図の追加」項で `tileUrl` に `http://`（非 https）や `javascript:` などを入力すると、フォームが**エラー表示して追加しない**（保存ボタンを押してもダイアログが閉じない）。

## 3. Phase 1 新規挙動: カスタム背景地図の追加（Req 7.1〜7.6）

- [ ] 7.1 一覧末尾の「**＋ 背景地図を追加**」ボタンが視覚的に確認できる（既存 4 種行と区切り線で分離、ボタンとして識別可能）。
- [ ] 7.2 「＋ 背景地図を追加」ボタンを押すと**モーダルダイアログ**が開く（背景が半透明黒で覆われ、地図操作が阻害される）。最初の入力フィールド（表示名）に**自動フォーカス**する。
- [ ] 7.3 フォームに以下のフィールドが表示される: **必須**＝表示名／タイル URL テンプレート／出典テキスト、**任意**＝出典リンク URL／最小ズーム／最大ズーム。必須フィールドには `*` 印が付く。
- [ ] 7.6 ダイアログを **ESC キー・取消ボタン・モーダル背景（dialog 要素自身）クリック**のいずれかで閉じる→ 入力値が破棄され、レジストリ（一覧）・永続化（localStorage）に**変更が加わらない**（ダイアログを再オープンすると空フォーム）。
- [ ] 7.4 有効入力（例: 表示名=`MyMap`、タイル URL=`https://tile.openstreetmap.org/{z}/{x}/{y}.png`、出典テキスト=`Test`）で保存すると、ダイアログが閉じ、**一覧末尾に `MyMap` 行**が追加される（追加行は組込み 4 種の後・「追加」ボタンの前）。
- [ ] 7.5 追加した `MyMap` を**選択**すると、組込みと同じく排他切替・地図表示の即時更新・出典追従（入力した「Test」が出典欄に表示）が起こる。
- [ ] 3.5 上記でカスタム選択時、出典に**利用者入力の `attributionLabel`**（および入力していれば `attributionLinkUrl` を href とする `<a>`）が表示される。

## 4. Phase 1 新規挙動: カスタム入力の検証（Req 8.1〜8.4）

各ケースで「追加」ボタン→ ダイアログを開き、以下を入力して**保存**を押す。期待結果は**ダイアログが閉じず、該当フィールド下に日本語エラー文言が表示され、一覧に追加されない**（最初のエラー入力にフォーカスが移る）こと。

- [ ] 8.1 必須欠落: 表示名／タイル URL／出典テキストのいずれかを空のまま保存 → 「○○は必須です」エラー。
- [ ] 8.2 タイル URL のプレースホルダ不在: `https://e.com/{z}.png` のような `{x}{y}` 欠如値で保存 → 「`{z}/{x}/{y}` のプレースホルダをすべて含めてください」エラー。
- [ ] 8.3 タイル URL の非 https: `http://e.com/{z}/{x}/{y}.png` で保存 → 「https:// で始まる必要があります」エラー。
- [ ] 8.4 ズーム不正: 最小=20、最大=5 を入力して保存 → 「最大ズームは最小ズーム以上」エラー。最小=`abc` 入力 → 「ズームは整数で入力してください」エラー。

## 5. Phase 1 新規挙動: 定義の永続化（Req 10.1／10.3／10.5）

- [ ] 10.1 上記 7.4 で `MyMap` を有効追加した後、**ブラウザを再読込（F5）**する → 一覧末尾に `MyMap` 行が**再表示**される（定義が永続化されている）。
  - 注: Phase 1 では選択状態の復元は未結線のため、再読込後の表示中背景は OSM のまま（Phase 0 と同じ初期挙動）。再読込後に手動で `MyMap` を選び直せば切替・出典追従が動作する。Req 1.6 改訂結線および選択復元（Req 10.6〜10.8）は Phase 2 task 13.x で実装・14.2 で確認。
- [ ] 10.3 DevTools の Network タブを開いた状態でカスタム追加を実行 → 追加に伴う `fetch`／`XHR`／`sendBeacon` リクエストが**発生しない**（外部送信なし）。
- [ ] 10.5 ストレージ強制失敗のシミュレーション: DevTools の Application > Storage > Local Storage を「Quota」上限まで埋める／無効化、または `localStorage.setItem = () => { throw new Error('Quota'); }` を Console で上書きしてから追加保存 → ダイアログが**閉じず**、aria-live 領域に「保存できませんでした（当該セッションのみ反映、再読込で消えます）」が表示される。一覧には in-memory で追加が反映される（再読込すると消える）。

## 6. Phase 1 新規挙動: a11y（Req 6.1〜6.4 非回帰＋C2 修正）

- [ ] 6.1 マウスを使わず **Tab／矢印キーのみ**で組込み 4 種＋カスタム追加分を選択・切替できる（矢印キーの連続移動で選択フォーカスが**消えない** — Phase 0 は同じ動作だが、Phase 1 では setBasemap 後に renderList を呼ばない局所更新化（C2）でフォーカス維持を明示的に保証している）。
- [ ] 6.2 スクリーンリーダ／ブラウザの読み上げで、各選択肢のラベル（組込み4種＋カスタム名）が読み上げられる。
- [ ] 6.3 現在選択状態が支援技術で判別できる（radio の checked 状態）。
- [ ] 6.4 コントロールが地図のパン／ズーム操作を妨げない位置・サイズで配置され、既存コントロール（左上／右上／右下）と重ならない。追加ボタン行・dialog 表示時も同様。

## 7. 既知のスコープ境界（Phase 1 では未動作）

以下は Phase 2 で実装・確認するため**本チェックリスト対象外**です:

- 編集ボタン（利用者エントリのみ）・編集ダイアログでの pre-fill（Req 9.1〜9.3／12.1〜12.2）
- 削除ボタン・削除確認・選択中削除時の OSM フォールバック（Req 9.4〜9.6／12.3）
- 選択状態の永続化（任意背景を選んで再読込で**当該背景が復元**される挙動／Req 10.6〜10.8）
- Req 1.6 改訂結線（永続化選択がない初回のみ OSM、ある場合は復元）
- フォーム a11y 仕上げ（最初のエラー入力への自動フォーカス制御の細部、Req 6.5）

これらは Phase 1 の本チェックリストでは**観測できないことが期待挙動**（追加ボタンは出るが編集ボタンは出ない、削除はできない、再読込時の選択は OSM に戻る、等）です。
